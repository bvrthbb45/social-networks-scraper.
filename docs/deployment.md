# פריסה (לולאה 9)

המערכת רצה ב-`docker compose` על שרת של היחידה. לא נדרש שום שירות חיצוני.

## מבנה
| רכיב | תפקיד | חשיפה |
|---|---|---|
| `proxy` | nginx: HTTPS, אפליקציית הווב, `/api/*` → API | היחיד שחשוף החוצה (80→הפניה ל-443, ‏443) |
| `api` | FastAPI | רשת פנימית בלבד |
| `daily` | תחזוקה יומית ב-03:00 UTC: שמירת נתונים, פקיעת הסכמות, ניקוי מדיה, ניתוח | רשת נתונים בלבד |
| `migrate` | הרצת מיגרציות לפני עליית ה-API | חד-פעמי |
| `db` | PostgreSQL 16 | רשת `internal` ללא יציאה החוצה |

כל הקונטיינרים: קריאה-בלבד, ללא הרשאות Linux, `no-new-privileges`. כתובת הלקוח האמיתית מגיעה מה-proxy בלבד (הוא **דורס** את `X-Forwarded-For`; ה-API סומך רק על רשת ה-edge), כך שהגבלת קצב, נעילת חשבון ויומן הביקורת מבוססים על כתובת אמיתית.

## התקנה ראשונה
1. שרת עם Docker ו-Compose. תעודת TLS של היחידה (`fullchain.pem`, `privkey.pem`) בתיקייה שלא בתוך הריפו. המפתח צריך להיות קריא ל-uid 101 (המשתמש של nginx).
2. `bash scripts/gen-secrets.sh` – יוצר `.env` (הרשאה 600) עם מפתחות חדשים וגם `.backup-passphrase`.
3. **העתיקו** את `FIELD_ENCRYPTION_KEY`, `BLIND_INDEX_KEY` ואת `.backup-passphrase` למקום בטוח **נפרד** מהגיבויים. בלעדיהם גיבוי אינו קריא, ואין דרך לשחזר.
4. הוסיפו ל-`.env`: `CERT_DIR=/הנתיב/לתעודה` ואת `ALLOWED_ORIGINS=` (ריק = אותו מקור בלבד, מומלץ).
5. `docker compose up -d --build --wait`
6. מנהל ראשון: `docker compose exec api python -m app.cli create-admin you@example.org` – מדפיס אסימון הזמנה חד-פעמי; פותחים את הכתובת ומשלימים סיסמה ואימות דו-שלבי.

## תפעול שוטף
- **גיבוי**: `bash scripts/backup.sh /נתיב/גיבויים` – מסד נתונים + קבצי ראיות, מוצפנים (AES-256, PBKDF2) עם סכומי בדיקה. לתזמן יומית (cron). הגיבויים מכילים מידע רגיש – אותה רמת הגנה כמו המערכת, ולא באותו מקום עם המפתחות.
- **שחזור**: `bash scripts/restore.sh /נתיב/גיבויים 20261007T030000Z` – מחליף את המצב הנוכחי, דורש להקליד `RESTORE`. מומלץ לתרגל על שרת בדיקה אחת לרבעון.
- **עדכון גרסה**: `git pull && docker compose up -d --build` (המיגרציות רצות אוטומטית).
- **החלפת מפתח הצפנה**: ראו `docs/data-protection.md` (הגדרת `FIELD_ENCRYPTION_KEY_ID` חדש והעברת המפתח הישן ל-`FIELD_ENCRYPTION_OLD_KEYS`).
- **מכשיר אנדרואיד**: מזינים באפליקציה את כתובת ה-HTTPS של השרת (ראו `docs/android.md`).

## מה נבדק אוטומטית
בדיקות `backend/tests/test_deploy_config.py` נועלות את תכונות האבטחה (אין יציאות חשופות מלבד ה-proxy, DB פנימי, קונטיינרים נעולים, דריסת כותרות, TLS 1.2+, HSTS, CSP ללא תוכן חיצוני). ב-CI רץ job ‏`deploy`: בונה ומעלה את כל המערימה עם תעודה זמנית, בודק HTTPS/כותרות/הפניה, יצירת מנהל, ריצת העבודה היומית וגיבוי מוצפן, ו-`shellcheck` על הסקריפטים.

## מגבלות ידועות
- שחזור (`restore.sh`) נבדק בקריאה ובבדיקת תחביר, לא הורץ מקצה לקצה ב-CI; יש לתרגל אותו לפני הסתמכות.
- הגיבוי המוצפן אינו מאומת-שלמות (חתימה); `SHA256-*.txt` מגן מפני שחיתות, לא מפני זדון – יש לאחסן גיבויים במקום מוגן מכתיבה.
- אין ניטור/התראות תפעוליות מובנים; מומלץ לעקוב אחרי `docker compose ps` ולוג ה-`daily`.
- תעודת TLS מנוהלת ידנית (ללא Let's Encrypt, כי השרת לא אמור לצאת לאינטרנט).
